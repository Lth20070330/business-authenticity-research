# 数据获取方案

## 首选：真实合作数据

依次评估授信机构、支付/收单机构、电商或 ERP 服务商、授权商户与财税服务商。可通过导师、校友、商会和产业园寻找入口；这些是待联系渠道，不是已达成合作。

最小合作需求：

- 稳定匿名商户与交易对手标识；时间、金额、收支类型。
- 可关联的订单、支付、退款与履约记录，注明覆盖范围。
- 申请或评估时点，以及当时可取得哪些数据。
- 独立复核证据、结论适用的交易/期间、结论确认时间。
- 研究使用、发表、保存期限与可公开内容的书面约定。

先申请小规模字段验证，不默认要求完整银行数据库。数据不能出机构时争取机构内运行代码、导出经审核的聚合评测结果。

## 公开数据备选

| 来源 | 用法 | 局限 |
| --- | --- | --- |
| Olist | 订单—支付—履约的经营背景 | 无本任务核验标签，非完整资金网 |
| Online Retail II | 交易时序与取消行为 | 单一零售商，无经营造假真值 |
| IBM AML-Data / AMLSim | 参考合成资金网络及模拟机制 | 合成洗钱任务与本题不同 |
| YelpCHI / DGraph | 辅助方法比较 | 标签与业务对象不同，不做主验证 |

从原始发布者取得数据，登记版本、下载日期、校验摘要和许可。不同来源不通过臆造 ID 拼成真实多源记录。无法确认许可的数据暂不再发布。

## 案例机制库

优先官方公开案例。提取来源 URL、事件时间、业务场景、行为机制、证据、确认范围和不可观察部分。案例描述用于设计与标注，不冒充交易明细。排名刷单不自动推断为授信欺诈；同一案件不同报道需去重。

## 立即执行

1. 在来源登记表列出候选合作方或数据源，避免写入私人联系方式。
2. 逐项核验字段、标签、覆盖、下载方式、许可与研究适配性。
3. 确定一个公开底座并完成数据质量小样本审计。
4. 取得真实核验机会后，优先建设独立测试集，再扩大训练数据。
